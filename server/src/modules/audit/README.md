# Audit events

This module stores only explicit, allowlisted administrator-bootstrap events. It does not add retroactive authentication, game, or general operational logging. Shared request-error behavior remains in `server/src/middleware/errors.js`.

`initializeAuditStorage(database)` creates the connection-bound `audit_events` collection and declared indexes. It does not seed, delete, synchronize, or drop data. The model uses `AuditEvent`, strict field handling, and disabled automatic collection/index creation.

`createAuditService(database, { now })` exposes `recordAuditEvent(input, { session })`. This slice persists only the committed bootstrap success; refusals/failures use fixed terminal guidance. The writer accepts only the declared event fields, owns `occurredAt` and the 90-day `expiresAt`, and can participate in a caller's Mongo transaction. A write failure produces a generic safe error and aborts bootstrap; the caller must not report success without the event. Unknown fields and invalid values produce a generic safe error without echoing keys or values. `actorKind: 'operator'` requires `actorId: null`; user actors require a 24-character hexadecimal ID. The initial event type is `admin.bootstrap`; the typed writer accepts success/refused/failure outcomes for future separately approved callers.

`listEvents(actor, query)` requires the current `admin:audit:read` capability before reading records. The `GET /api/admin/audit-events` route is session-protected and no-store. Only eventType/from/to/page/limit are accepted; repeated, unknown, object/operator and prototype-named inputs are rejected. Date filters are valid UTC ISO timestamps ending in Z, with optional one-to-three fractional digits, bounded to a non-future window of at most 90 days. Defaults are the last 90 days, page 1 and 20 rows; maximum page is 10,000 and maximum limit is 50. Expired records are excluded even before background TTL deletion. Results sort by newest event time and ID, and the response is `{ events, page, total }`. Each event returns only eventType/actorKind/actorId/targetId/scopeCohortId/outcome/occurredAt/requestId; dates are ISO strings and IDs strings or permitted nulls. GET does not write audit records.

Audit events contain no free-text fields, credentials, passwords, hashes, tokens, cookies, request bodies, stacks, or connection details. `requestId` is a UUID used only for correlation. The writer does not generate authentication or game events; those require separate approved integration work.
